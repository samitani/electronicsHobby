# 縦型LED反射神経ゲーム 仕様書

**バージョン：2.2**

## 1. プロジェクト概要

縦一列に配置した60個のLEDを使用する、反射神経・アクションゲーム。

スマートフォンのブラウザをコントローラーとして使用し、Wi-Fi経由でESP32と通信する。

### 基本構成

- LED：縦一列、合計60個
- LEDの色：RED / GREEN / BLUE
- コントローラー：スマートフォンのWebブラウザ
- 通信方式：Wi-Fi / WebSocket
- ゲーム処理：ESP32側で実行
- 操作画面：スマートフォンのブラウザに表示
- 専用アプリやインターネット接続は不要

## 2. ゲームモード

以下の3種類のゲームモードを用意する。

1. TIMING GAME
2. COLOR SHOOTING
3. COLOR BATTLE

---

## 3. TIMING GAME

### 3.1 ゲーム概要

上から落下してくる光の色と、落下位置・タイミングに合わせてスマートフォンのボタンを押すゲーム。

光は連続して自動的に出現し、プレイヤーの入力を待たずに次の光が落下する。

プレイを続けるほど落下速度と光の出現間隔が変化し、徐々に難易度が上がる。

### 3.2 光の落下

- 光はLEDの上端から下端に向かって落下する。
- 光は一定の間隔で連続して出現する。
- プレイヤーのボタン入力を待たずに、次の光が自動的に出現する。
- 複数の光が同時に落下することがある。
- 各光の色はRED / GREEN / BLUEからランダムに決定する。

### 3.3 プレイヤーの操作

- スマートフォンにRED / GREEN / BLUEの3つのボタンを表示する。
- 光が下端のターゲット位置に到達するタイミングで、光と同じ色のボタンを押す。
- 色とタイミングの両方が正しい場合に成功とする。

### 3.4 成功・失敗判定

- 判定位置はLEDの下端に設けるターゲット位置とする。
- 初期の許容範囲は中央LEDを基準に±1 LED（合計3 LED）とする。
- 光の色と押されたボタンの色が一致し、かつタイミングが許容範囲内であれば成功。
- 色またはタイミングが正しくない場合は失敗。
- ターゲット位置を通過するまでに正しい入力がなかった光も失敗とする。

### 3.5 スコア・連続成功数

- 成功するとスコアを加算する。
- 成功すると連続成功数（STREAK）を加算する。
- 失敗すると連続成功数を0にリセットする。
- 成功時は緑色、失敗時は赤色の演出を表示する。

### 3.6 自動難易度調整

難易度選択は設けない。

ゲームの進行に応じて、以下の要素を徐々に変化させる。

- 光の落下速度を徐々に速くする。
- 光と光の出現間隔を徐々に短くする。
- 難易度の上昇には上限を設ける。

ゲームが進むにつれて、より短い時間で複数の光に対応する必要がある。

### 3.7 ライフ・ゲームオーバー

- ゲーム開始時のライフは3。
- 光を正しく処理できなかった場合、ライフを1減らす。
- ただし、色の違うボタンを押しただけではミスとはカウントしない。光が処理できなかったときのみミスとする。
- 成功してもライフは回復しない。
- ライフが0になった時点でゲームオーバーとする。
- つまり、3回ミスするとゲームオーバーとなる。

### 3.8 ゲーム終了時の表示

- 最終スコア
- 最大連続成功数
- ゲームオーバー表示
- リスタートボタン

## 4. COLOR SHOOTING

### 4.1 ゲーム概要

上から落下してくる複数の光に対して、スマートフォンから同じ色の光を発射し、衝突させて消していくゲーム。

### 4.2 光の落下

- RED / GREEN / BLUEの光が上から落下する。
- 複数の光が同時に落下する。
- 落下する光の色はランダムに決定する。

### 4.3 プレイヤーの操作

- スマートフォンにRED / GREEN / BLUEの3つのボタンを表示する。
- ボタンを押すと、対応する色の光を下端から上方向に発射する。

### 4.4 衝突判定

落下する光と、プレイヤーが発射した光が衝突した場合、以下のように処理する。

| 衝突条件 | 結果 |
|---|---|
| 同じ色 | 両方の光が消える。スコアを加算する |
| 異なる色 | 発射した光だけが消える。落下する光はそのまま進む |

### 4.5 自動難易度調整

難易度選択は設けず、プレイの進行に応じて自動的に難易度を上げる。

以下の要素を徐々に変化させる。

- 落下する光の速度を徐々に速くする。
- 落下する光の出現間隔を徐々に短くする。
- 同時に落下する光の数が増えるようにする。
- 難易度の上昇には上限を設ける。

ゲームが進むにつれて、より多くの光に短時間で対応する必要がある。

### 4.6 ゲームオーバー

- 落下する光が下端に到達するとゲームオーバー。
- ゲーム終了時に最終スコアを表示する。
- リスタートボタンを表示する。

## 5. COLOR BATTLE

### 5.1 ゲーム概要

2人のプレイヤーがボタンを押し合い、LED上の陣地を奪い合う対戦ゲーム。

LED60個を2人で分け、それぞれの色の領域を広げていく。

### 5.2 初期状態

- LED60個を30個ずつに分割する。
- プレイヤーAの領域をREDにする。
- プレイヤーBの領域をBLUEにする。
- 初期状態では両者の領域は同じ大きさとする。

### 5.3 プレイヤーの操作

- プレイヤーAはREDボタンを押す。
- プレイヤーBはBLUEボタンを押す。
- ボタンを押した回数をそれぞれ累積カウントする。

### 5.4 陣地の変化

2人の累積ボタン押下回数の差によって陣地を変化させる。

- 相手より10回多くボタンを押すごとに、LED1個分の陣地を獲得する。
- 押下回数の差が10回未満の場合、陣地は変化しない。
- 押下回数の差が縮まった場合、陣地も中央方向に戻る。
- したがって、陣地は累積押下回数の差に応じて常に決定される。

### 5.5 陣地計算例

| プレイヤーA | プレイヤーB | 回数差 | Aの陣地増加 |
|---:|---:|---:|---:|
| 100 | 90 | 10 | 1 LED |
| 120 | 90 | 30 | 3 LED |
| 125 | 90 | 35 | 3 LED |
| 100 | 100 | 0 | 0 LED |
| 90 | 100 | -10 | Bが1 LED獲得 |

計算方法：

`陣地の変化量 = floor(累積押下回数の差 / 10)`

差の正負によって、どちらのプレイヤーが陣地を獲得するかを決定する。

### 5.6 勝利条件

- 相手の領域をすべて奪い、LED60個すべてが自分の色になった時点で勝利。
- 勝利したプレイヤーを表示する。

### 5.7 画面表示

- プレイヤーAの累積押下回数
- プレイヤーBの累積押下回数
- それぞれの陣地数
- 勝敗結果

## 7. 通信・ソフトウェア構成

### 7.1 接続方式

- ESP32がWi-Fiアクセスポイントとして動作する。
- スマートフォンからESP32のWi-Fiに接続する。
- スマートフォンのブラウザから `http://192.168.4.1` にアクセスする。
- WebSocketで双方向通信を行う。

### 7.2 ESP32側の役割

- ゲーム状態の管理
- LEDの点灯制御
- 光の出現・移動処理
- 衝突判定
- ボタン入力の判定
- スコア計算
- ライフ管理
- 自動難易度調整
- COLOR BATTLEの陣地計算
- ゲームオーバー判定

### 7.3 スマートフォン側の役割

- ゲームモード選択画面の表示
- 操作ボタンの表示
- ボタン入力の送信
- スコア・ライフ・ゲーム状態の表示
- COLOR BATTLEの対戦情報の表示

### 7.4 通信メッセージ

スマートフォンからESP32への主なメッセージ：

| メッセージ | 内容 |
|---|---|
| START | ゲーム開始 |
| PRESS_RED | REDボタン入力 |
| PRESS_GREEN | GREENボタン入力 |
| PRESS_BLUE | BLUEボタン入力 |
| RESTART | ゲーム再スタート |
| SET_MODE | ゲームモード設定 |

ESP32からスマートフォンへの主なメッセージ：

| メッセージ | 内容 |
|---|---|
| GAME_STATE | ゲーム状態 |
| SCORE_UPDATE | スコア更新 |
| STREAK_UPDATE | 連続成功数更新 |
| LIFE_UPDATE | 残りライフ更新 |
| HIT | 成功通知 |
| MISS | ミス通知 |
| GAME_OVER | ゲームオーバー通知 |
| BATTLE_UPDATE | COLOR BATTLEの陣地・押下回数更新 |
| WINNER | 勝者通知 |
